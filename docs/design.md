# 设计与实现说明

## 为什么是纯 JS、不带构建

Obsidian 插件最终加载的就是 `main.js`。官方模板用 TypeScript + esbuild，好处是类型检查，代价是使用者要 `npm install` 才能改。

这个项目选择**手写 CommonJS 的 main.js**：

- 用户下载三个文件就能装，不用 Node
- 贡献者改一行、重启 Obsidian 就能看到效果
- 没有构建产物与源码不一致的问题

代价是没有类型检查和打包优化。等代码量再大（比如超过 3000 行）再迁 TypeScript 更划算。

## 数据流

```
笔记 (Markdown)
   │  parseContent()  按行状态机
   ▼
题库 items[]（内存）
   │  id = hash(文件 + 题干)
   ▼
progress{wrong, srs, stats}  →  data.json（本库）
```

题库**不持久化**：每次启动从笔记重建，所以改了笔记、重开 Obsidian 就是最新的。
只有进度持久化，键是 `item.id`（文件路径 + 题干做哈希），所以题干改一个字，这道题的进度会重置——这是有意的取舍，避免错题记到另一道题头上。

## 解析规则

逐行扫描，空行分题：

| 行首 | 含义 |
| --- | --- |
| `Q:` / `问：` | 题干，开始新题 |
| `A.` `B、` `C)` `D：` | 选项（A—E） |
| `答案:` / `正确答案:` / `答：` | 答案，支持字母或选项原文 |
| `解析:` / `说明:` / `考点:` | 解析 |

答案规范化：能对上字母就用字母；写的是选项原文就反查字母；都对不上则丢弃这道题（宁缺毋滥）。
没有选项行的题 → `type: 'card'`，进背诵。

## 间隔重复

简化版 SM-2：每张卡有 `ease`（0—4）和 `due`。

- 记住：`ease += 1`，下次间隔 `SRS_DAYS[ease]` = 1 / 3 / 7 / 15 / 30 天
- 忘了：`ease = 0`，明天再来

不够精细，但对「考前一个月」这个场景够用，而且规则透明、不会出现「算法算出 90 天后复习」的荒谬结果。

## AI 接入

只依赖 OpenAI 兼容的 `/chat/completions`，用 Obsidian 的 `requestUrl`（绕开 CORS、不用额外权限）。

- **讲解**：题干 + 选项 + 答案 + 已有解析 → 三段式讲解（为什么对 / 别的错在哪 / 易混点）
- **出题**：当前笔记前 6000 字 → 要求只输出 JSON 数组 → 解析后弹窗，可一键插入笔记

失败策略：接口非 2xx、返回不是 JSON、内容为空，都会抛错并 `Notice` 提示，不静默失败。

## 隐私

- 默认零网络请求
- Key 存在 `data.json`（本库内），不写日志
- 只有用户主动点 AI 按钮才发送当前题 / 当前笔记

## 已知局限

1. 格式敏感：一行写错（比如用了全角冒号之外的分隔）就解析不到
2. 没有导入预览：批量导入后只能看总数
3. 移动端侧栏空间小，选项长时体验一般
4. 题库全量进内存，几千题没问题，几万题需要分页/索引
5. 没有按考点筛选（`考点:` 行目前只被存进解析，未单独建字段）
